## 問題

AI 生成介面時，容易為每個區塊附上解釋，讓使用者在真正操作前先閱讀一段不必要的文案。

## 做法



- 原貼文提出可直接給 Agent 的約束：不要解釋性、冗長文案，只顯示必要內容與元素。
- 原文沒有截圖、前後對照或具體產品；因此本卡收錄的是文字方法，沒有宣稱任何畫面已實作或證明更易用。

## 為什麼有效（推論）

把文案是否幫助辨識狀態、選擇與下一步作為刪減依據，可能降低介面掃讀成本；但必要資訊不能只由字數判斷。

## 借鑑要點

- **適合**：AI 產出的設定頁、工具列與重複說明很多的初稿。
- **不適合**：首次使用必須理解的權限、付款、資料刪除和錯誤恢復說明。
- **移植時注意**：逐句標記用途：標籤、狀態、操作後果或輔助說明。先刪重複，再用任務測試確認沒有增加猜測；風險與後果應留在操作附近。
