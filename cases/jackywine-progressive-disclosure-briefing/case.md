## 問題

Agent 每天主動推送大量資訊，使用者卻不一定有時間讀完。如何保留發現筆記關聯的主動性，又讓使用者控制何時繼續？

## 做法

[原帖](https://x.com/Jackywine/status/2122527571187531866)的官方公開 HTML 包含完整 NoteTweet，本卡已讀全文並檢視附帶的 7.166 秒影片，沒有以嵌入摘要替代全文。作者稱這是自己使用的 bot；按自用流程展示收錄為 concept，沒有驗證可公開使用的產品。平台只記錄影片所示的 Mac 桌面情境。

- **作者規則**：每天從 flomo、X 列表與 Obsidian 知識庫找出筆記間的關聯，先提供一組內容；若使用者沒有回覆，就不繼續打擾。這是作者對行為的說明，並非本卡實測。
- **畫面中的第一組內容**：深色對話視窗內，bot 的訊息靠左，以題目、筆記來源和相關筆記列開頭，再提供舊筆記與當下的連結解讀；沒有把所有資料排成單一大報表。
- **觸發 → 回應 → 停留狀態**：影片開始時已存在一則靠右、暖色底的使用者回覆，下方隨後可見 bot 的延伸回應。回應先引用使用者說法，再延續同一主題；底部保留輸入框及新訊息提示。短片沒有呈現從零輸入、送出回覆的完整操作，也沒有展示第二組內容解鎖。
- **證據邊界**：影片展示對話串與捲動，不能證明整天未回覆時不再推送，也不能確認停止規則是否跨日持續、如何重啟或是否提供略過操作。原文沒有交代這些規則。

影片包含個人筆記與對話，本卡只保留流程觀察與原文連結，不保存截圖、私人內容逐字稿或原始影片。

## 為什麼有效（推論）

- 把回覆作為繼續交流的條件，可能讓推送速度貼近使用者當下投入程度；這不代表已測得閱讀率提升。
- 第一組內容帶有筆記來源和關聯線索，可能讓使用者更容易提出自己的判斷，再由 Agent 延伸，而非只被動接收摘要。
- 將延伸回應留在同一對話串，可能減少找回上下文的負擔。來源未提供成效或長期使用數據。

## 借鑑要點

- **適合**：非緊急的個人知識回顧、學習提問、研究靈感與定期閱讀推薦。
- **不適合**：必須確實送達的緊急告警、到期提醒，或使用者不回覆也必須完成的流程。
- **移植時注意**：明確告知每次先推多少、什麼操作會繼續、略過與暫停有何差別；定義隔日是否重新開始，避免把沉默當作同意。這些是移植建議，不是影片已具備的功能。
