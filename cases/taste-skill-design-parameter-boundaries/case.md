## 問題

讓 Agent 生成介面時，如何表達設計取向，避免只說「高級一點」？

## 做法

- 原帖沒有圖片或影片；文字明確提出三個可調面向：佈局實驗程度、動畫豐富度與資訊密度。
- 作者把通用、極簡、粗野主義和舊專案審查列為不同方向，並描述先生成設計稿、再交給編碼工具實現的兩段流程。
- 這些是作者對工具的介紹；原帖未展示調整前後的同頁比較，也沒有參數範圍，因此本卡不聲稱其效果已驗證。

## 為什麼有效（推論）

把三個面向分開，可能讓團隊更清楚討論取捨，例如保守佈局仍可保有適量回饋；也避免把某種風格直接等同於可用性。

## 借鑑要點

- **適合**：給 Agent 的視覺需求、設計方向比較與舊頁面審查。
- **不適合**：以風格參數代替使用者任務、內容結構和可及性。
- **移植時注意**：為每個面向補具體例子與可檢查標準；先用同頁內容比較候選，再驗證小螢幕、效能和減少動態效果。不安裝 skill 也能使用此需求拆解法。
