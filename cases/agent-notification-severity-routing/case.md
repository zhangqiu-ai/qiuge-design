## 問題

Agent 已完成或遇到重要情況，但單一 webhook 不一定能即時觸達離線使用者。

## 做法

- 原帖提出需求而非展示已實作產品：普通消息走 webhook 與應用內通知，P1 發短信，P0 打電話。
- 作者以飛書和釘釘的消息加急作類比，未定義各層級判定與升級超時。

## 為什麼有效（推論）

依處理急迫性選擇通道，可能兼顧日常安靜與重大事件可見度；錯誤分級也可能造成騷擾。

## 借鑑要點

- **適合**：長任務 Agent 的事件通知設計。
- **不適合**：將每次進度更新都升級成電話。
- **移植時注意**：先定義 P0/P1 的具體觸發、去重與確認機制；讓使用者設定安靜時段和升級偏好。
